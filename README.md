# OpenHPSC Community

**Building an open foundation for dependable computing in space.**

This repository is the coordination space for OpenHPSC. We use it to discuss
ideas, investigate technical questions, record architecture decisions, and agree
on the next steps toward an open-source, high-performance, fault-tolerant
space-computing platform.

[Documentation](https://openhpsc.github.io/) ·
[Discussions](https://github.com/openhpsc/community/discussions) ·
[Issues](https://github.com/openhpsc/community/issues) ·
[Roadmap](ROADMAP.md)

## Start here

- **Introduce yourself or share an idea** in [Discussions](https://github.com/openhpsc/community/discussions).
- **Propose a bounded task** in [Issues](https://github.com/openhpsc/community/issues).
- **Investigate an open question** using the [research index](research/README.md).
- **Review a design choice** through the [architecture decision records](adrs/README.md).
- **Submit an improvement** by following [Contributing](CONTRIBUTING.md).

## Current focus

OpenHPSC is in its definition phase. Our immediate priorities are to identify
one useful workload, compare a small set of open hardware candidates, and define
a first experiment that another contributor can reproduce.

Research, technical review, embedded software, FPGA design, verification, and
documentation contributions are welcome. You can help before a processor or
board has been selected.

## What belongs here

| Location | Purpose |
| --- | --- |
| Discussions | Introductions, questions, and exploratory ideas |
| Issues | Actionable work with a clear expected result |
| `research/` | Research questions, literature reviews, and investigation notes |
| `adrs/` | Significant architecture decisions and their rationale |
| `ROADMAP.md` | Milestones, priorities, and completion criteria |

The [documentation repository](https://github.com/openhpsc/openhpsc.github.io)
hosts the published manuals and guides. Report website and documentation defects
there. Use this community repository for work that shapes the project as a whole.

Keep implementation code and large experimental datasets in the appropriate
implementation or research repository when those exist; link them from here.

## Working together

Start with a question, gather evidence, discuss the alternatives, and record the
outcome. Small corrections can go directly into a pull request. Significant
design choices should be discussed before they are treated as accepted decisions.

OpenHPSC is an independent initiative, not an open-source release of Microchip's
PIC64-HPSC or an affiliated NASA/JPL project.
